# System Context

## Purpose
Instapress is a desktop app that loads the caption and image of one of the user's own Instagram posts or reels, lets the user edit the text in a rich text editor with a photo attached, and creates it as a publication post (a draft) on a WordPress site.

## Context (C4 level 1)
- **User**: the person who curates publications and owns or has permission to publish the content.
- **Instagram API** (external): `graph.instagram.com`, Instagram Login flavor, read-only, for the user's own account. Scraping the public web does not work: without a session Instagram serves an empty page with no caption.
- **Instagram image CDN** (external): the backend downloads the post's picture from `*.cdninstagram.com` or `*.fbcdn.net` when the user chooses it as the post image.
- **WordPress site** (external): target of the post, reached through its REST API with an Application Password stored in the OS credential store.

## What exists today
- The main window has two tabs under a header that stays on screen while the panel scrolls:
  - **Credentials**: the Instagram access and the WordPress access.
  - **Editing**: the list of recent posts and the draft (hidden until a post is selected).
- Selecting a post fills the draft with its caption (title, editable rich text) and lets the user choose the image. "Create draft" sends the post to WordPress as a draft and shows the address where it can be reviewed and published.
- The window has a menu bar: **File > Exit**, **View > 2 columns** and **Help > About Instapress**. See [`ui-design.md`](ui-design.md).

See [`../domain/instagram-api.md`](../domain/instagram-api.md), [`../domain/publication-draft.md`](../domain/publication-draft.md), [`../domain/wordpress.md`](../domain/wordpress.md), [`../domain/instagram-url.md`](../domain/instagram-url.md) and [`http-client.md`](http-client.md).

## Not implemented yet
Paging beyond the first 25 posts, screenshots of a post, tags and the primary category of the theme, scheduling and publishing directly (posts are always created as drafts), and carousel images beyond whatever single picture the API reports for the album.

## Containers (C4 level 2)
One Tauri v2 process:
- **Rust backend** (`src-tauri/`): library crate `instapress` plus the binary `instapress` (`src/gui/main.rs`). The binary keeps one `AppState` with the Instagram token store, the WordPress settings store and one HTTP client.
- **Static frontend** (`ui/`): `index.html`, `app.css`, `app.js`, embedded at compile time and talking to the backend through Tauri IPC (`withGlobalTauri`).

## Modules
- `instagram_url`: pure URL classification.
- `token`: `AccessToken`, the `TokenStore` trait and `KeyringStore`, plus `OsSecret`, the one named secret of the OS credential store that the Instagram and WordPress stores share (service `instapress`, a different user name for each).
- `http`: the blocking `ureq` client and its rules (see [`http-client.md`](http-client.md)).
- `instagram_api`: the `HttpGet` trait, response parsing, `Post`, `ApiError`, `list_recent_posts` and the trusted image host check.
- `publication_html`: caption to HTML (with the publication sections as headings), the suggested title and the body without it, HTML sanitizing and the validated `PublicationDraft`.
- `image`: `Image`, the three `ImageChoice`s, `data:` URL decoding, the `ImageFetcher` trait and `ImageError`.
- `browser`: `check_admin_url` and `open_in_browser`, which hand the address of a draft to the system's default browser (`rundll32 url.dll,FileProtocolHandler` on Windows, `open` on macOS, `xdg-open` elsewhere) as a single argument, never through a shell. Only a page under `{saved site}/wp-admin/` is opened, with no whitespace or control character.
- `wordpress`: `SiteUrl`, `AppPassword`, `WpCredentials`, the `CredentialsStore` trait and `KeyringCredentials`, the `WpHttp` trait, `create_draft`, `CreatedPost` and `WordPressError`.
- `video`: the Instagram player that can go below the text of a draft, and the link that jumps to it (`VideoChoice`, `VideoEmbed`).
- `publish`: `DraftInput`, `PublishError` and `publish_draft`, the whole flow in the order that spends the least.

## IPC commands
All are thin adapters over the library, declared in `build.rs` and granted to the `main` window in `capabilities/main.json`. Errors reach the frontend as plain strings. The autogenerated `permissions/autogenerated/*.toml` files that Tauri derives from `build.rs` are committed.
- `set_layout_menu(two_columns)`, `prepare_draft(caption)`, `suggest_slug(title)`: fast, run inline. `set_layout_menu` sets the check mark of View > 2 columns when the window starts.
- `prepare_draft(caption)` and `suggest_slug(title)` are pure. `prepare_draft` returns `{ title, html, slug, meta_description }`: the suggested title, the body without the title line (with the sections of the publication as headings), the slug of the title and a suggested meta description. `suggest_slug` makes the slug of a title as the user types it.
- `token_status()`, `save_token(token)`, `refresh_token()`, `renew_token_if_due()`, `clear_token()`: the Instagram token and its renewal. The status holds whether there is a token and when it expires; saving a token also remembers an assumed expiry (see [`../domain/instagram-api.md`](../domain/instagram-api.md)).
- `get_wordpress_settings()`, `save_wordpress_settings(site, username, app_password)`, `clear_wordpress_settings()`: WordPress access. The first returns `{ site, username, has_password }`, never the password.
- `open_in_browser(url)`: opens the edit address of a created draft in the browser. It loads the saved site and refuses any address that is not under its `wp-admin` folder.
- `list_posts()`, `list_categories()`, `create_wordpress_draft(draft)`: network work.

Every command that touches the credential store or the network is `#[tauri::command(async)]`, so it runs on Tauri's own runtime instead of the UI thread. Such a command holds one of that runtime's workers while it waits, which the client timeouts bound. There is no async runtime of our own (ADR 0001).

## Main window behavior
- **Tabs** follow the WAI-ARIA tabs pattern: a `tablist` with two `tab` buttons, each controlling a `tabpanel`; only the selected tab is a tab stop (`tabindex`), the left and right arrows move between the tabs (wrapping), Home and End go to the first and the last, and only the selected panel is shown. The panel itself can take focus, so a keyboard user can scroll it.
- **Which tab opens**: the credentials are read from the credential store, which is quick, before any network call. If there is an Instagram token that has not expired and the WordPress settings are saved, the window opens on **Editing**; otherwise on **Credentials**.
- **A mark on the Credentials tab** (a dot, and the text "(needs attention)" for a screen reader) shows while the token is missing or expired, or the WordPress settings are missing. It goes away when everything is in place.
- **Without a token** the list of posts shows a message with a button to go to Credentials, instead of an empty list; Refresh is disabled.
- **The list of recent posts** shows **four rows** and scrolls inside its own box, not the whole window. Each row has a fixed height (picture, the type and date, and two lines of the caption), so the box is exactly four rows tall, with a shadow at the edge that still has more to show. With fewer than four posts the box is as tall as they need, and with none it is not shown. The box can take focus, so it scrolls with the keyboard.
- When the window scrolls to the draft it leaves room for the header.
- On start the token is renewed if it is due (a failure only shows a message), and then, if one is saved, the recent posts load automatically. The Instagram block says when the token expires and has a "Renew now" button; saving a token reloads them and removing it clears the list. A Refresh button reloads them. Only the newest list request may update the page and Refresh is disabled while one is in flight.
- Each post shows a 72 px preview, a type label (Photo, Reel or video, Album, Post), the date in the viewer's locale and the caption cut at two lines, or "(no caption)". Selecting one opens the draft and moves the focus to its title.
- The draft has a title field (at most 200 characters), a rich text editor, a Categories block (a list with a box for each category, indented by its depth in the tree and with a search that ignores case and accents, loaded from the site the first time a draft is opened and with a Reload button), a Date field (it starts with the date of the Instagram post and can be changed or emptied), an SEO block (the slug, which follows the title until the user edits it, the focus keyphrase and the meta description with a character counter), the image choice, a "show the video" checkbox that appears only for video posts and a "Create draft" button. The toolbar (bold, italic, heading, bullet list, numbered list) has an accessible name on every button; pressing the heading button on a heading turns it back into a paragraph. Pasting into the editor inserts plain text.
- The image choice defaults to the post's picture, with a 96 px preview, and to "No image" when the post has none (the option is then disabled). Choosing a file shows its name and size, rejects one over 10 MB and selects the file option. If the file option is selected with no file read, publishing is blocked with a message.
- After "Create draft" the window shows the edit address in a read-only field with an **Open in browser** button and a Copy button; if the browser cannot be started the message says so; if the clipboard is not available it selects the text and says to copy it by hand. If the answer never arrived, the message adds that the draft may still exist.
- Everything Instagram or WordPress sends is rendered as text (`textContent`), never as HTML. The editor is the only HTML the page produces: it is filled with HTML that the backend built with every special character escaped, and its content goes back to the backend, which sanitizes it before sending it on.
- Errors are announced as alerts, everything else as status messages.
- Secret fields (Instagram token, Application Password) are password inputs and are emptied as soon as Save is pressed, whether or not the save works. The WordPress site and user name are shown again from the saved settings.

## Security
Content Security Policy: `default-src 'self'`, `script-src 'self'`, `style-src 'self'`, `connect-src` only for the Tauri IPC endpoint (`ipc:` and `http://ipc.localhost`), `img-src` limited to the app itself and the Instagram CDN (`*.cdninstagram.com`, `*.fbcdn.net`) with no `data:` images, and `base-uri`, `form-action`, `object-src` and `frame-ancestors` all `'none'`. `freezePrototype` is on. All HTTP requests are made by the Rust backend, never by the webview. The Instagram token and the Application Password live only in the OS credential store and are never sent back to the frontend or logged. The capability grants the window exactly the fifteen commands above and the permission to listen to events (for the menu), and no file, shell or HTTP permission.

## Dependencies
`tauri` (without default features), `ureq` with `rustls` (blocking HTTP), `keyring` (OS credential store), `serde`/`serde_json`, `base64` (data URLs and HTTP Basic), `ammonia` (HTML sanitizing, ADR 0003), `thiserror` and `anyhow`.
